Run only the checks your change needs.

Verifika is a small verification CLI for developers and coding agents. List your checks once. vfk runs only the ones your change affects and says exactly what failed.

$ npm install --save-dev verifika
GitHub npm

Node.js 22.13 or newer · MIT licence

How it works

  1. 1

    Define your checks

    One verifika.config.json lists each check's command and the files that can affect it.

  2. 2

    Verifika selects

    It compares your work with git, then matches paths, dependsOn and invalidateAll. vfk plan shows each decision.

  3. 3

    Run and read

    Selected checks run one at a time, or in parallel up to the limit you set. A pass is a short summary; a failure names the check, the cause and where the full log is.

verifika.config.json 
{
  "$schema": "./node_modules/verifika/schemas/verifika.schema.json",
  "version": 1,
  "changes": {
    "invalidateAll": ["package.json", "package-lock.json", "tsconfig*.json"]
  },
  "checks": {
    "format": { "command": "npm run format:check" },
    "lint": { "command": "npm run lint", "paths": ["src/**/*.{ts,html}"] },
    "typecheck": { "command": "npm run typecheck", "paths": ["src/**/*.ts"] },
    "test": { "command": "npm test", "paths": ["src/**", "test/**"] },
    "build": { "command": "npm run build", "paths": ["src/**"], "dependsOn": ["typecheck"] }
  }
}

Why Verifika

  • Selective locally, complete in CI

    On your machine, only checks whose files changed run. In CI and with --all, every check runs.

  • Deterministic

    Selection comes from config, globs, dependencies and git. No heuristics, no LLM. When the scope is unclear, it runs everything.

  • Parallel, in order

    Independent checks share a concurrency limit. dependsOn orders the rest; if a dependency fails, its dependents are reported as blocked.

  • Small output for agents

    One line on success, a bounded preview on failure. A failing test that printed 94,900 bytes is reported in 369.

  • Results you can trust

    Timeouts, fail-fast, exact exit codes, and process-tree cleanup. Tested on Linux, macOS and Windows.

  • Logs on disk, not in your context

    Full output of every check is kept in .verifika/. Read it when you need it with vfk logs.

Get started

Terminal 
npm install --save-dev verifika
npx vfk init     # config and verify scripts from package.json
npx vfk plan     # what would run for your changes, and why
npx vfk          # run the checks your changes affect
npx vfk --all    # run every check, before you push and in CI

vfk init maps conventional scripts like lint, test and build to checks. Add paths to each so local runs can skip what a change can't affect.

Using a coding agent? The README has a setup prompt that installs Verifika, writes the config for your repository, and adds the agent skill.
